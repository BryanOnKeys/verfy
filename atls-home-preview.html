Control what your AI agents do. Prove what they did.

01 The product

Four controls. One record you can trust.

Each works on its own on a developer's laptop. Together they answer: what did the agent do, with which tool, and who allowed it?

01 · Atls Guard

Checks every step before it runs

Shell commands, file writes, web requests, SQL and payments are checked against your policy. Every answer is allow, ask or deny, with the rule and the reason.

02 · Atls Scan

Finds risky MCP servers

Reads Claude Code, Cursor and Claude Desktop settings and flags hidden instructions, unpinned packages, plain-HTTP servers and leaked keys.

03 · Atls Lock

Tools can't change behind your back

The first time a tool is used, Atls pins the SHA-256 of its exact definition. If it changes later, it is blocked until a person reviews the difference.

04 · Atls Receipts

A record that proves itself

Every decision becomes a receipt, signed on the device with Ed25519 and chained to the one before it with SHA-256.

02 How it works

In the path of every tool call

Atls decides on your machine, without waiting for the network. The web platform collects evidence; it is never in the way.

Running in two minutes

The CLI is plain Python with no required dependencies, and it never touches the network from inside a check.

# not on PyPI yet: install from a copy of the Atls repository
$ pip install ./atls-cli
$ atls init
$ atls hook install --write
$ atls check "rm -rf ~"
03 Evidence

Records that prove themselves

Every receipt is linked to the one before it, so changing a record after the fact breaks the check exactly where it was changed. Once receipts reach Atls Team, the server keeps their hashes and refuses a rewritten history, even one signed with the device's own key.

05 Questions

Straight answers

Atls only claims what it can show. Its known limits are listed in docs/SECURITY_LIMITATIONS.md in the repository.

Does an AI decide what my agent may do?

No. Every verdict comes from deterministic rules: the same input always gets the same answer, and you can read, test and change the rules. No language model is ever asked whether something is allowed.

What happens if Atls itself fails?

It fails safe. A broken policy, an unreadable lock file or an internal error becomes "ask" (or "deny", if you choose). Atls never lets an action through because something went wrong.

Does my code leave my computer?

No. Checks run locally and never wait for the network. If you join a team, only receipts are uploaded, and by default they hold hashes of the arguments, not the arguments. Private keys never leave the device.

Is Atls a sandbox?

No. Atls checks what passes through its hook or gateway. For untrusted code, use it together with OS-level isolation such as a container or a virtual machine.

Can someone with access to my machine rewrite the record?

Not one record at a time: any edit, deletion or reordering makes the check fail at that spot. But whoever holds a device's private key could build a whole new chain from scratch and sign it, and that chain would check out on its own. That is why receipts sync to Atls Team: the server keeps the hash of every receipt it has received and refuses a different one in the same place. A ledger that never left the machine has no such outside copy.

What does it cost?

The CLI is free, under the MIT license. Atls Team is free software too: it runs on your own Vercel and Supabase projects, so you pay only what they charge you.
